## 0. 测试前准备

### 0.1 自动化测试（每次改代码后先跑）

```bash
npm test                    # 前端单元测试（mock 业务规则、请求层、工具函数）
npx vue-tsc --noEmit        # 类型检查
cd server && go test ./...  # 后端测试
```

三条都要通过。

### 0.2 前端：用 mock 数据看页面（不需要后端）

1. 把 `src/api/client.ts` 里的 `USE_MOCK` 临时改成 `true`（**测完记得改回 `false`**）。
2. `npm run dev:mp-weixin`，等出现 `Build complete`。
3. 微信开发者工具 → 导入 `dist/dev/mp-weixin`。
4. mock 里的“我”是店主（阿柚），客人端和店主端入口都能看到。mock 数据每次重新编译后会重置。

### 0.3 后端：本机启动（不需要 MySQL）

```bash
cd server && go build -o jingyu-local.exe .
```

```bash
STORE=memory PAY_MODE=fake PORT=8091 OWNER_OPENIDS=owner-1 FAKE_PAY_OPENIDS=tester-1 ./jingyu-local.exe
```

- `STORE=memory`：数据放内存，重启就没了。
- 身份靠请求头 `X-WX-OPENID`：`owner-1` 是店主，`tester-1` 是能用假支付的测试人员，其他任意值是普通客人。
- 用 curl / Postman 调 `http://127.0.0.1:8091/v1/...`，例如：

```bash
curl -s http://127.0.0.1:8091/v1/shop
```

```bash
curl -s -H "X-WX-OPENID: owner-1" "http://127.0.0.1:8091/v1/owner/schedule?date=2026-10-10"
```

- 订阅消息在内存模式下只打日志（`subscribe msg (not sent)`），在后端终端里看。

### 0.4 真机 / 云托管联调

`USE_MOCK=false`（默认），小程序走 `wx.cloud.callContainer` 连云托管服务 `jingyu-api`。店主身份由云托管环境变量 `OWNER_OPENIDS` 决定；客人要测付定金，得把自己的 openid 加进 `FAKE_PAY_OPENIDS`。订阅消息、拨号、地图、加日历、分享朋友圈只有真机能完整验证。

## 三、后台规则（需要等时间或用后端测）

| 规则 | 怎么测 | 预期 |
|---|---|---|
| 付款超时自动取消 | 下单不付，等过付款期限（或在 mock 里改系统时间） | 变已取消，原因“付款超时”，时段放出 |
| 店里没确认自动取消 | 付了定金店主不确认，到开始时间 | 变已取消，定金原路退回 |
| 已确认自动完成 | 过了开始时间 + 时长 | 变已完成，进“已完成” |
| 退款进度 | 取消付过定金的预约 | 已取消 → 退款中 → 已退回 |
| 到店提醒 | 已确认的预约，开始前一天 18:00 后 | 客人收到到店提醒（内存模式看日志） |
| 店主变动提醒 | 店主额度 > 0 时，客人付定金/改期/取消 | 店主收到“预约变动提醒”，额度减 1；额度 0 不发，不影响客人操作 |
| 假支付权限 | 普通客人调 `/bookings/:id/fake-paid` | 403“现在还不能在线付定金，请联系门店预约” |
| `PAY_MODE` 不设 | 不带 `PAY_MODE` 启动后端 | 直接退出，提示要设置 |
| 公开接口 | 不带 openid 调 `/shop` `/services` `/works` `/artists` `/dates` | 正常返回；调 `/me` 返回 401 |
